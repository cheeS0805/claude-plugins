# Дебаг: спершу причина, потім виправлення

Головне правило: **не вгадувати**. Не міняй код «а раптом допоможе». Спершу доведи, ЩО саме і ЧОМУ зламано, — тоді виправлення буде одне й точне. Якщо в проєкті є CLAUDE.md із розділом про відомі пастки — прочитай його першим.

## 1. Відтворити

Добийся, щоб баг повторювався стабільно, і запиши як.

| Що зламано | Чим відтворити |
|---|---|
| вигляд / верстка | скриншот сторінки (headless Chrome `--screenshot`, або перевірка проєкту, якщо вона їх робить); вузький телефон — сторінка в iframe потрібної ширини (headless Chrome не вміє вікно вужче ~500px) |
| кліки, анімації, «відчуття» | справжній браузер — Claude in Chrome (`@browser`) |
| JS-помилка | консоль браузера |
| збірка | команда збірки окремо — читай першу помилку й номер рядка |
| хук | подай хуку JSON **з файлу**: `node hook.mjs < test.json` (bash у командному рядку їсть `\\` і лапки) |

Не вдалося відтворити — не виправляй. Спитай: що саме робили, на якому пристрої, скриншот.

## 2. Ізолювати

- Порівняй «працює» і «не працює»: що різне (ширина екрана, файл, браузер, режим)?
- `git log` / `git diff` — з якого коміту почалось?
- Виміряй, а не дивись на око: `getBoundingClientRect()`, `scrollWidth` проти `clientWidth`, розмір файлу, код виходу.

## 3. Знайти справжню причину

Запитуй «чому?», доки не дійдеш до коренів. Часті пастки:

| Симптом | Справжня причина |
|---|---|
| сторінка ширша за телефон, смуга збоку | блок із `aspect-ratio` + `min-height` розтягується вшир → `max-width: 100%`; шукай елемент, у якого `right > clientWidth` |
| заголовок ховається під шапкою після кліку по якорю | «липка» шапка → `scroll-padding-top` на `html` |
| хук «нічого не робить», вивід порожній | Windows: `process.exit()` губить асинхронний stdout → `writeSync(1, …)` |
| пошук не знаходить рядок, який точно є у файлі | файл із `\r\n`, а шукаємо `\n` → нормалізувати переноси |
| перевірка завжди ✅ | тест нічого не ловить → **зворотний тест** (тимчасово зламай і переконайся, що червоніє) |
| правка в згенерованому файлі «зникла» | файл перезаписує збірка → правити джерело |

Знайшов причину — поясни її користувачу простими словами **до** виправлення.

## 4. Виправити

- Мінімальна правка саме в причині, не в симптомі. Згенеровані файли не чіпай — правиш джерело.
- Якщо хук після правки повернув ❌ — це підказка, а не перешкода.
- Біля неочевидного виправлення — короткий коментар «чому так».

## 5. Довести, що полагоджено

- Повтори **той самий** спосіб відтворення — і покажи цифри «до → після».
- Проганяй перевірку проєкту — усе ще ✅?
- Якщо баг може повернутися — додай перевірку й зроби зворотний тест.
- Новий тип пастки — допиши в CLAUDE.md проєкту.
- Запропонуй коміт із поясненням причини і спитай перед комітом.
